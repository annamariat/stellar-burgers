# Stellar Burgers

Космическая бургерная: веб-приложение, где можно собрать бургер из ингредиентов, оформить заказ, посмотреть ленту заказов и историю своих заказов в личном кабинете.

**Демо:** https://annamariat.github.io/stellar-burgers/

## Возможности

- **Конструктор бургера.** Выбор булки, начинок и соусов, счётчики на карточках, перемещение и удаление ингредиентов, подсчёт стоимости.
- **Детали ингредиента.** Открываются в модальном окне по клику и отдельной страницей при прямом переходе по ссылке `/ingredients/:id`.
- **Лента заказов `/feed`.** Доступна всем: стоимость каждого заказа, количество заказов за всё время и за сегодня, автообновление каждые 15 секунд и кнопка «Обновить».
- **Авторизация.** Регистрация, вход, выход, восстановление пароля. Сессия сохраняется после перезагрузки страницы.
- **Личный кабинет.** Редактирование профиля с кнопками «Отменить» и «Сохранить», история заказов `/profile/orders` со статусами.
- **Оформление заказа.** Только для авторизованных пользователей, гостя перенаправляет на страницу входа. После заказа конструктор очищается, лента и история обновляются.
- **Страница заказа.** `/feed/:number` и `/profile/orders/:number` открываются модальным окном или отдельной страницей при прямом заходе.
- **Страница 404** для неизвестных адресов.
- **Анимации модальных окон.** Плавное открытие и закрытие в космическом стиле, учитывается системная настройка «уменьшить движение».

## Архитектура

### Хранилище (Redux Toolkit)

Состояние разделено на независимые слайсы в `src/services/slices`:

| Слайс | За что отвечает |
| --- | --- |
| `ingredientsSlice` | Загрузка списка ингредиентов, флаги загрузки и ошибки |
| `constructorSlice` | Булка и начинки в конструкторе: добавление, удаление, перемещение, сброс |
| `feedSlice` | Лента заказов, общее количество и количество за сегодня |
| `userSlice` | Пользователь, регистрация, вход, выход, обновление профиля, проверка сессии |
| `ordersSlice` | Создание заказа, история заказов, заказ по номеру |

Селекторы вынесены отдельно в `src/services/selectors`, компоненты не обращаются к структуре состояния напрямую. Асинхронные запросы реализованы через `createAsyncThunk`, для каждого есть состояния `pending`, `fulfilled` и `rejected` (лоадеры и сообщения об ошибках).

### Маршрутизация

- Модальные окна работают через `background location`: страница остаётся под окном, адрес в строке меняется, кнопка «Назад» закрывает окно.
- `ProtectedRoute` защищает закрытые страницы (профиль, история заказов) и закрывает страницы для гостей от уже вошедших (вход, регистрация, восстановление пароля). Пока проверяется сессия, показывается прелоадер. После входа пользователь возвращается на страницу, с которой пришёл.

### Авторизация

- `accessToken` хранится в cookie, `refreshToken` в `localStorage`.
- При истёкшем токене запрос автоматически обновляет его и повторяется (`fetchWithRefresh`).
- При старте приложения `checkUserAuth` восстанавливает сессию.

## Преимущества подхода

- **Разделение логики и отображения.** Компоненты в `components` работают с данными, а `components/ui` только рисуют разметку по пропсам. Их проще тестировать, переиспользовать и показывать в Storybook.
- **Предсказуемое состояние.** Единое хранилище и чистые редьюсеры: любое изменение данных можно проследить.
- **Типобезопасность.** Строгий TypeScript, типизированные `useDispatch` и `useSelector`, явные типы возвращаемых значений у селекторов.
- **Масштабируемость.** Новый слайс добавляется одним файлом и одной строкой в `rootReducer`.
- **Единообразный код.** Линтеры, Prettier и pre-commit хуки не пропускают в репозиторий неотформатированный код.
- **Хороший UX.** Прелоадеры при загрузке, понятные сообщения об ошибках, плавные модальные окна, сохранение сессии.
- **Изолированные стили.** CSS Modules исключают конфликты имён классов.

## Запуск проекта

1. Установить зависимости:

        npm install

2. Создать в корне файл `.env`:

        BURGER_API_URL=https://norma.ffapi.ru/api

3. Запустить в режиме разработки (http://localhost:4000):

        npm start

## Публикация

Сайт публикуется на GitHub Pages командой `npm run deploy`. Для корректной работы:

- в `vite.config.ts` задан `base: '/stellar-burgers/'` для production-сборки;
- в `BrowserRouter` указан `basename`;
- при сборке создаётся копия `404.html`, чтобы обновление страницы на вложенных маршрутах не приводило к ошибке.
